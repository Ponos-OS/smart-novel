# Backend refactor: NestJS to Go (entgql), Nx to Taskfile

> **Working agreement: one step, then stop for review.**
>
> - Work on exactly one step at a time, following `.github/docs/process/PROCESS.md` and `SELF_IMPROVE.md` where they still apply.
> - Finish the whole step first: code, tests, the step's "Verify" list, the self-improvement log. Do not ask for review, and do not ask the user to look at anything, before that.
> - Then stop, summarize what was done and anything that deviates from the step, and wait for the user's review. Do not start the next step until the user says so.
> - Leave the step uncommitted until the user approves. On approval commit on the current branch with a message naming the step number. Do not push; nothing is pushed until the whole refactor is done.
> - The app is allowed to be broken between steps. Each step still states what must work at its end.

## Decisions already made

- Backend: Go with [ent](https://entgo.io) and `entgql` (gqlgen underneath). Ent replaces Prisma.
- Task runner: [Taskfile](https://taskfile.dev) replaces Nx. `task` is a system tool, never an npm dependency: installed with apt on developer machines, with `go-task/setup-task` in CI and with the official install script (pinned release) in Docker images. Scripts and docs call `task`, never `npx task`. Nx, `project.json`, `nx.json` and every `@nx/*` dependency go away.
- `libs/shared` goes away. Rules both apps need live in one JSON spec; the constants for each language are generated from it. The small helper functions are copied by hand into each language.
- Anything a task can regenerate is git-ignored and never committed: generated shared constants, ent code, gqlgen code, the GraphQL schema, frontend GraphQL types. Docker builds, CI and `task` dependencies must run generation first.
- `APP_ENV` (`development`, `production`, `test`) replaces `NODE_ENV` as the backend's own setting, including the Go backend. `NODE_ENV` stays only where Node tools read it (the frontend Dockerfile, Vite, Vitest).
- The frontend stays TypeScript/React/Vite; only its tooling changes.
- `apps/backend-e2e` and `apps/frontend-e2e` stay TypeScript. The backend e2e suite talks to the API over HTTP only, so it is the parity oracle for the port: the Go backend is done when that suite passes against it.

## Project layout

Go modules are tied together by a root `go.work`; the frontend and e2e projects stay plain npm projects. The Go layout follows the ent/entgql/gqlgen conventions (`ent/schema`, `ent/entc.go`, `ent/generate.go`, `gqlgen.yml`) and the usual `cmd/` + `internal/` split.

```
Taskfile.yml                    root tasks, includes the per-app Taskfiles
go.work                         use ./apps/backend ./tools
spec/
  shared.json                   constants, messages, roles, patterns
  cases/*.json                  helper-function cases, loaded by Go and TS tests
tools/                          its own Go module
  genshared/                    reads spec/, writes the TS and Go constants
apps/
  backend/                      Go module (go.mod, Taskfile.yml, gqlgen.yml, Dockerfile, .air.toml)
    cmd/server/main.go          wiring only: config, dependencies, run
    api/
      *.graphql                 only what ent cannot derive: custom queries/mutations, computed or viewer fields (committed)
      ent.graphql               generated by entgql (ignored)
    ent/
      schema/*.go               one file per entity (committed)
      entc.go, generate.go      entgql extension and go:generate hooks (committed)
      migrate/migrations/       versioned Atlas SQL (committed)
      *                         everything else generated (ignored)
    internal/
      config/                   env parsing
      server/                   HTTP router, middleware, health, GraphQL handler
      graph/                    gqlgen resolvers, thin: authorize, call a service, map errors
        generated.go, model/    generated (ignored)
      auth/                     ZITADEL JWT, viewer in context, authorization functions
      <domain>/                 novel, chapter, tag, writer, license, stats, ...: services and business rules
      platform/                 adapters: redis, objectstorage, rabbitmq, beatrice, fithara, otel
      shared/                   generated constants (ignored) and hand-written helpers
  frontend/                     Vite app; src/generated/ ignored
  backend-e2e/                  vitest, HTTP only
  frontend-e2e/                 Cypress
  backend-nest/                 the old NestJS app, kept as a reference until step 11, not built
infra/                          terraform, scripts, observability
.github/
```

Rules:

- A domain package never imports `internal/graph` or `internal/server`; resolvers import domain packages. Domain packages talk to the outside world through interfaces they own, implemented in `internal/platform`.
- The API schema is generated from the ent schema, not written by hand: entgql (`WithSchemaGenerator`, `WithSchemaPath("../api/ent.graphql")`, `WithWhereInputs(true)`, `WithConfigPath`, `entgql.Mutations(...)`, `entgql.OrderField`, `entgql.RelayConnection`) emits the entity types, enums, connections, ordering, filters and create/update inputs. Hand-written files in `apps/backend/api` only `extend` it with operations that are not entity CRUD and with computed or viewer-specific fields such as `Chapter.isRead`. `gqlgen.yml` and the frontend codegen both read `apps/backend/api/*.graphql`.
- Ent schema files hold fields, edges, indexes, validators and `entgql` annotations only; business rules go in the domain package.
- Tests sit next to the code (`*_test.go`), table-driven, except integration tests that need Postgres, which carry a build tag or live under `internal/<domain>/integration`.

## Step 1: Taskfile replaces Nx

Remove Nx from the workspace and drive everything with Taskfile. The backend is untouched in this step.

- Root `Taskfile.yml` with `includes` for `apps/frontend`, `apps/backend`, `apps/backend-e2e`, `apps/frontend-e2e`. Tasks keep the names people use today (`lint`, `test`, `build`, `codegen`, `e2e`, `storybook`, `generate`), namespaced per app (`task frontend:build`).
- Tasks declare `sources`/`generates` so regeneration is skipped when nothing changed.
- `npm run start:dev`, `stop:dev`, `format`, `lint`, `clean` and `infra/scripts/*` call `task` instead of `nx`/`npx nx`. `clean` removes every generated path.
- Delete `nx.json`, every `project.json`, the `@nx/*` and `nx` dev dependencies, Nx eslint plugin config, and `NX_*` env in Dockerfiles and terraform. Frontend runs Vite, Vitest, Storybook and Cypress directly.
- Add every regenerable path to `.gitignore` (start with the ones that exist: `apps/frontend/src/generated`, `apps/backend/schema.gql`, `storybook-static`, `coverage`, `dist`) and `git rm --cached` anything already tracked there.
- Husky and lint-staged are replaced by Lefthook (`lefthook.yml`: eslint and prettier on staged files, prisma format, and lint plus tests on pre-push). `core.hooksPath` is unset and `.husky` is deleted.
- `libs/shared` stays for now; the frontend and backend keep resolving it through `tsconfig.base.json`. Step 2 removes it.

Verify: `task --list` shows the tasks; `task frontend:lint`, `frontend:test`, `frontend:build` and `frontend:storybook:build` pass; `git grep -iE "\bnx\b"` finds only history and docs listed for step 11; the NestJS backend still starts under `npm run start:dev` (it may call its own scripts directly instead of Nx).

## Step 2: Shared spec and generator, delete `libs/shared`

- `spec/shared.json` at the repo root: every constant, error code, message, the role list and hierarchy, and the pen-name pattern as a regex source string. Messages that interpolate constants (`A pen name needs at least {WRITER_PEN_NAME_MIN_LENGTH} characters`) use `{NAME}` placeholders that the generator resolves.
- Patterns stay in the subset JS and Go (RE2) share: no lookaheads, no backreferences. The generator fails on anything else it recognizes.
- `spec/cases/*.json`: input and expected output pairs for the helper functions (`hasMinimumRole`, `isAdmin`, `isWriterOrHigher`, `getPenNameProblem`).
- The generator is a Go program at `tools/genshared`, run by `task generate:shared`. It writes `apps/frontend/src/generated/shared.ts` and `apps/backend/internal/shared/shared_gen.go` (both git-ignored). The generator is its own Go module under `tools/`, tied in by a root `go.work`, so it runs before the backend module exists.
- Helper functions are written by hand in both languages next to the generated files (`apps/frontend/src/shared/*.ts`, `apps/backend/internal/shared/*.go`) and both test suites load `spec/cases/*.json`. Go counts runes, not bytes, for length checks.
- `toUtcDay` is only ported if the Go backend turns out to need it (check in step 3).
- Frontend imports move from `@smart-novel/shared` to the generated file and the local helpers. Delete `libs/`, the `@smart-novel/shared` path in `tsconfig.base.json`, the `COPY libs` lines in the Dockerfiles, the `libs` volume in `infra/terraform/local/1-app`, and the "libs/shared" paragraph in `CONTRIBUTING.md`. The NestJS backend is allowed to break on its imports of the shared package.

Verify: `task generate:shared` is idempotent; `task frontend:test` and `go test ./...` for the helpers pass against the same case files; a deliberate edit to a case file fails both suites; frontend typechecks with no reference to `@smart-novel/shared`.
